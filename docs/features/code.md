# Programming Assistant

Use Programming Assistant to discuss code, algorithms, debugging, and implementation
trade-offs. You do not need uploaded documents for ordinary coding questions.

## Ask for the thinking you want to practise

> Explain why this loop skips an element. Ask me to identify the invariant before showing a fix.

> Review this implementation of binary search. Focus on termination and boundary cases.

> Compare these two approaches for a technical interview. What assumptions should I say aloud?

Include the language, relevant code, expected behaviour, and the exact error when
asking for debugging help. Avoid pasting access keys, credentials, or private data.

## Use your documents when they help

Enable **Use my documents** to bring indexed material into the response. This is
useful for course notes or a coding exercise specification. The toggle is unavailable
when the knowledge base is empty.

## Verify suggested code

The assistant explains and proposes code; it does **not** execute a solution or
prove that it passes tests. Run the code in your own development environment,
check edge cases, and compare claims with the relevant language or library documentation.

For an interview session with saved results and structured follow-ups, use
[Technical Interview in Preparation Coach](coach.md).
